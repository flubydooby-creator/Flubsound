Flubsound Pro - test build
==========================

Written by Flubes and Claude (co-authors).

This is an unsigned test build made by CI from the commit in VERSION.txt.
It is for trying the app out, not a release. Start with your headset volume
LOW: Flubsound can add gain (Boost, bass, the maximizer).

Contents
--------
  Flubsound Pro(.exe / .app)   the desktop app (tray, 4 strips, presets)
  Plug-ins/VST3                Flubsound FX plug-in for a DAW
  Plug-ins/AU                  (macOS only) Audio Unit version
  Plug-ins/Standalone          the plug-in as a small standalone app

Installing
----------
  Windows: two ways, both in the Flubsound-windows download:
           - FlubsoundPro-Setup-<version>.exe installs the app into
             Program Files, the VST3 plug-in into
             C:\Program Files\Common Files\VST3, a Start menu entry and an
             uninstaller (Settings > Apps > Flubsound Pro > Uninstall; your
             settings and presets in %APPDATA%\Flubsound are kept).
           - or run "Flubsound Pro.exe" straight from the Flubsound-windows
             folder, nothing installed.
  macOS:   open Flubsound-macos.dmg and drag Flubsound Pro onto
           Applications (Flubsound-macos.zip has the same files). Plug-ins:
           copy Plug-ins/VST3/Flubsound FX.vst3 to
           ~/Library/Audio/Plug-Ins/VST3 and Plug-ins/AU/Flubsound FX.component
           to ~/Library/Audio/Plug-Ins/Components.
  Linux:   tar -xzf Flubsound-linux.tar.gz; cd Flubsound-linux; then either
           run "./Flubsound Pro", or ./install.sh to install it for your user
           (a menu entry, ~/.local/bin/flubsound-pro, the VST3 in ~/.vst3;
           ./install.sh --uninstall removes it). Needs PipeWire or
           PulseAudio, ALSA and X11 or XWayland.

Opening an unsigned build
-------------------------
  Windows: SmartScreen says "Windows protected your PC" (for the installer
           and the app) -> More info -> Run anyway.
  macOS:   right-click the app -> Open -> Open (first launch only). If macOS
           says it is damaged, run in Terminal:
               xattr -dr com.apple.quarantine "/Applications/Flubsound Pro.app"

Getting sound into Flubsound
----------------------------
Flubsound processes other apps' audio and plays it on your headset.
  1. Settings > Audio: pick your headset as the OUTPUT device.
  2. Feed it audio, one of:
     Windows 10 (2004+) / 11: per-app capture is automatic. Open the routing
       panel and put your game / music / chat apps on a strip. Set those
       apps' own output to a device you do not listen to (Windows Settings >
       Sound > Volume mixer), or switch on Settings > Routing > "Move the
       app's own sound away automatically", so you do not hear them twice.
       When Flubsound sets an app's own device back (you unassign it or
       quit), an app that is playing may stay silent until you restart its
       playback (reload, or pause and play): Windows moves only new sound.
     Any OS: install a virtual cable (VB-CABLE on Windows, BlackHole on
       macOS), make it the system output, and pick its "Output" side as the
       input device in Settings > Audio. Settings > Routing > "Input feeds
       strip" chooses which strip gets it (Game by default).
     Linux: the flubsound_game / _music / _chat / _system sinks (see
       platform/linux in the repository) route apps per strip.
  3. Choose a mode (Music / Gaming) and a preset per strip.

Turtle Beach headsets
---------------------
Built-in profiles: Stealth, Recon, Atlas / Elite Atlas, Elite Pro, ROCCAT,
PDP, and headsets on the Xbox Wireless adapter, plus a generic Turtle Beach
fallback. A profile is picked from the OUTPUT device's name. To check that
yours was recognised, look at the banner in the main window or at
Settings > Audio, which shows "<your device>  -  Turtle Beach Stealth series"
(or the matching series) and the safety ceiling. A profile caps the output
level for the headset and may suggest a preset; if it says "generic device",
tell us the exact device name Windows / macOS shows.

Unplug the USB dongle while something plays: Flubsound moves to your
speakers at -6 dB with its virtual surround off and bass at most +3 dB (a
banner says so), and moves back when you plug it in again, also into another
USB port, where Windows names it e.g. "Headset Earphone (2- Stealth 700 Gen
2)". A headphone correction you imported (Settings > Correction) stays with
the headset. Settings > Audio > "Follow the system default output" plays on
whatever Windows uses as its default instead. Please tell us if any of this
does not happen.

Reporting a problem
-------------------
Flubsound keeps a log (device changes, errors, glitches and overloads; no
audio) and writes a crash report if it crashes. Settings > Diagnostics >
Export diagnostics saves both, with your settings and device details, as one
zip: attach it to your report. Your home folder, login and computer name are
replaced in it. Settings > Diagnostics also shows the Logs folder (next to
your user presets) and opens it:
  Windows: %APPDATA%\Flubsound\Logs
  macOS:   ~/Library/Flubsound/Logs
  Linux:   ~/.config/Flubsound/Logs

Updates
-------
Flubsound does not look for updates unless you ask it to. Settings >
Diagnostics > Updates > "Check for updates (notify only)": when it is on,
Flubsound asks GitHub at most once a day at start whether a newer release
exists (Stable, or Beta to include pre-releases) and tells you, with a link to
its download page. It never downloads or installs anything itself. On Linux
the check uses the curl program.

Not in this build (needs hardware work first)
---------------------------------------------
  - Flubsound's own virtual sound devices (Windows driver, macOS audio
    device): use per-app capture or a virtual cable instead.
  - Real-device latency has not been measured; the readouts are estimates.
  - The Windows and macOS builds pass their automated tests in CI but have
    not yet been run by a person. Please report what you find: device
    names, what worked, what did not, and screenshots.
